# RecBole Random-Play有效观看率优化设计

## 目标

提升 `GET /api/video-segments/random-play` 的线上有效观看率。第一阶段把“有效观看”定义为：用户观看该视频片段的时长达到片段时长的 60%。本阶段只调整 random-play 使用的 RecBole 训练与评估闭环，不改变搜题推荐链路。

## 现状与问题

- 训练默认使用 BPR，但导出的 `rating` 和 `weight` 没有形成清晰的隐式反馈语义；曝光、短看和踩可能被当作普通交互。
- 同一用户和片段的事件在导出时只按时间保留一条，当前逻辑可能让较新的低价值曝光覆盖较早的有效观看。
- RecBole 配置未明确按时间切分，随机评估无法准确模拟线上“用过去行为预测下一次观看”。
- 最近本地训练数据规模约 256 条交互，优先保证标签和评估可信度，不先增加复杂模型。

## 设计

### 1. 训练事件语义

导出器为每条用户-片段事件生成训练类别：

- 正样本：观看比例 `>= 0.60`；以及点赞、双击喜欢。有效观看优先级高于普通点击。
- 弱正样本：点击但观看比例低于 `0.60`，仅用于可选的低权重信号，不得与有效观看等价。
- 负样本：曝光未点击、明确踩、点击后未形成有效观看。负样本不作为 BPR 的正交互输入；如 RecBole 需要隐式交互文件，则通过负采样或显式负反馈配置表达。

同一用户和片段保留最新事件，但按语义优先级合并：有效观看或点赞不能被后续普通曝光覆盖；明确踩只在没有更高优先级正反馈时作为负反馈。导出阶段输出各来源、类别和正负数量统计。

### 2. 时间切分与评估

训练使用时间序列切分：每个用户按时间排序，最后一条可评估的正样本作为验证/测试目标，训练只使用此前事件。配置显式固定随机种子、评估模式和负采样参数，确保重复运行可比较。

离线报告至少包含 `Recall@20`、`NDCG@20`、`Hit@20`、`Precision@20`，以及按 60% 阈值计算的有效观看代理指标。报告同时记录样本总量、用户数、正样本数、负样本数和每个来源占比；样本不足时门禁失败，不发布模型。

### 3. 发布与线上边界

继续使用现有 baseline 对比和 active model 发布机制。新模型必须满足基础指标阈值、相对 active 模型不显著下降，并通过数据质量门禁；失败时 active 版本保持不变。线上 random-play 的候选召回和去重逻辑保持不变，本阶段不加入新的重排特征。

## 组件边界

- `video-service/tools/export_recbole_dataset`：事件查询、标签归类、去重合并、统计输出。
- `recbole-training/src/recbole_recommendation/config.py`：时间切分、评估和采样配置。
- `recbole-training/src/recbole_recommendation/train.py` 与 `metrics.py`：运行配置、保存有效观看代理指标和数据统计。
- `recbole-training/src/recbole_recommendation/publish_gate.py`：增加样本质量与有效观看指标门禁，沿用 active baseline 保护。

## 错误处理

导出查询失败、字段解析失败、样本为空或正样本不足时流水线直接失败，不生成可发布 artifact。门禁失败不得更新 `recsys` active model version。统计信息随 `metrics.json` 保存，便于定位训练质量问题。

## 测试与验收

- Go 单元测试覆盖 60% 阈值边界、事件优先级合并、踩与有效观看冲突、统计计数和 SQL 扫描字段。
- Python 单元测试覆盖时间切分配置、固定评估参数、有效观看指标归一化和数据质量门禁。
- 使用一组固定 fixture 运行训练配置检查，确认生成的 `metrics.json` 包含指标与样本统计。
- 验收标准：旧数据语义问题有回归测试；新流水线可生成 artifact；门禁失败不发布；线上 random-play 读取新 active 版本且 API 契约不变。

## 非目标

本阶段不更换为复杂多级反馈模型，不实现双阶段重排，不调整搜题推荐，不修改数据库表结构，也不删除旧推荐表。
