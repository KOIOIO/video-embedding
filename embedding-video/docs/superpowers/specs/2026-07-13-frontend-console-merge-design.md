# HLS Web 与推荐控制台合并设计

## 背景

仓库当前包含两个独立的 Vue 3 + Vite 前端：

- `hls-web/`：视频服务调试台，覆盖系统指标、上传、转码、播放、视频管理、反馈、题库和推荐联调。
- `recommendation-console/`：推荐管理控制台，覆盖诊断、概览、数据源、效果、链路追踪、Redis 状态和预览调试。

两个项目使用相同的 Vue、Vite 和 Vitest 技术栈，但分别构建和启动。根目录 Docker Compose 只部署 `hls-web/`，推荐控制台没有独立部署入口。推荐控制台现有登录只是浏览器内固定账号校验，后端没有登录接口、会话、令牌或 API 鉴权。

本次合并后只保留 `hls-web/`，将推荐控制台迁入同一应用，并删除整个 `recommendation-console/` 目录。

## 已确认决策

1. 合并后的唯一前端项目为 `hls-web/`。
2. 使用一个统一登录页和一份可伪造的客户端 UI 解锁状态控制两个工作区的界面显示；该状态不保护页面资源或后端 API。
3. 前端继续比较固定字符串 `aaddmmiinn` 和 `admin123` 作为 UI 门禁；它们不是安全凭据或可信用户身份。
4. 登录仍是前端页面门禁，不增加后端登录接口或 API 鉴权。
5. 登录后使用顶部一级切换在“视频调试台”和“推荐控制台”之间切换。
6. 两个工作区保留各自现有的内部导航和业务功能，不合并成一个超长仪表盘。
7. 非活动工作区必须卸载，避免两个工作区的轮询和资源同时运行。
8. 推荐控制台功能和测试迁移完成且验证通过后，删除 `recommendation-console/`。

## 安全边界

固定账号密码会出现在前端构建产物中，登录状态也可通过浏览器存储伪造。后端管理接口仍可被直接调用。因此统一登录只能减少误操作和隐藏页面入口，不能作为安全边界，也不能对外宣称具备访问控制能力。

真实鉴权、角色权限、从认证主体派生 `user_id`、保护管理 API、登录过期和密码管理均不在本次范围内。

在后端管理 API 增加真实鉴权或由可信网关保护前，本应用及其管理 API 不得暴露到不受信任网络。

## 方案比较

### 方案 A：统一侧栏工作区

一个侧栏同时承载两个业务域及其子导航，整体一致性最好，但需要重写两个项目的导航和较多页面布局。

### 方案 B：顶部双控制台切换

统一应用壳负责登录、工作区切换和退出；两个工作区内部继续使用现有导航。该方案迁移风险较低，能完整保留现有功能和交互。用户已选择此方案。

### 方案 C：单页综合仪表盘

把两个项目的全部模块放入同一长页面，会使多个轮询同时运行，并进一步扩大现有超大组件的维护成本，因此不采用。

## 应用架构

### 统一应用壳

`hls-web/src/App.vue` 只负责以下职责：

- 读取和更新统一登录状态。
- 未登录时显示统一登录页。
- 登录后显示品牌栏、工作区切换控件、当前账号和退出按钮。
- 读取、更新和恢复最后打开的工作区。
- 使用 `v-if` 只挂载当前工作区组件。

工作区切换使用顶部的两个分段式按钮，不增加 Vue Router 或 Pinia。应用初始化时读取并校验最后工作区；没有有效记录时使用 `video`。登录不重置工作区，因此首次登录进入视频调试台，刷新或退出后再次登录时恢复最后一个有效工作区。工作区和子栏目不写入 URL，浏览器前进、后退和深链接不参与导航。

### 视频工作区

现有 `hls-web/src/App.vue` 的视频业务内容迁入 `hls-web/src/workspaces/VideoWorkspace.vue`。现有 API、分片上传、ZIP 批量进度、播放器、系统指标、视频管理、题库、推荐、反馈和观看上报行为保持不变。

现有页面锚点继续作为视频工作区的内部导航。视频工作区每次挂载时重新初始化业务数据和所需轮询；卸载时停止系统指标、转码状态和 ZIP 进度等全部定时器，并释放工作区创建的播放器、HLS 实例和事件监听。重新进入时不得复用已卸载实例或启动重复轮询。

### 推荐工作区

`recommendation-console/src/App.vue` 的业务内容迁入 `hls-web/src/workspaces/RecommendationWorkspace.vue`，删除其内部登录页和退出逻辑。以下七个栏目必须保留：

- 诊断中心
- 概览
- 数据源
- 命中效果
- 链路追踪
- Redis 状态
- 预览调试

推荐 API helper、`PreviewTable.vue` 和内部导航配置迁移到 `hls-web/src/recommendation/`。推荐工作区每次挂载后重新加载诊断、概览、数据源和效果数据，应用壳不缓存这些业务状态；链路、Redis 和预览继续按用户操作加载。卸载时清理推荐工作区创建的全部定时器和事件监听。

## 状态与存储

统一登录模块将凭据校验、存储值解析和有效性校验实现为纯函数，并通过可注入的存储适配器集中封装 `window.localStorage` 读写，便于在 Vitest 中测试：

- 登录状态键：`video_app-console.authenticated`
- 当前工作区键：`video_app-console.active-workspace`
- 推荐子栏目键：继续使用 `video_app-recommendation-console.active-section`

登录状态以字符串 `"true"` 表示 UI 已解锁；缺失或任何其它值均视为未解锁。有效工作区只有 `video` 和 `recommendation`，未知或损坏的值回退到 `video`。推荐子栏目同样按七个已知栏目校验，未知、已删除或损坏的值回退到诊断中心。退出时只清除统一 UI 解锁状态，保留最后工作区和推荐子栏目，便于下次登录恢复上下文。

新应用不得读取或复制旧键 `video_app-recommendation-console.authenticated`，启动时删除该旧键。没有新的 UI 解锁标记时显示登录页。合并上线后用户需要使用固定账号密码重新登录一次；该迁移只避免意外继承旧状态，不构成安全措施。

视频上传断点和 ZIP 批次的现有存储键保持不变，确保未完成上传仍可恢复：

- `video-upload:<name>:<size>:<lastModified>`
- `video-archive-progress`

## 样式与响应式设计

应用壳新增少量独立类名，覆盖登录页、顶部品牌栏、工作区分段控件、当前账号和退出按钮。顶部区域在窄屏下换行，按钮文字不得截断或与账号操作重叠。

两个工作区和应用壳必须实现双向样式隔离。推荐控制台样式迁入独立样式文件：原页面级 `body` 样式改写到 `.recommendation-workspace` 根节点本身，其余元素和通用类选择器以该根节点为前缀。同时审计 `hls-web/src/style.css` 的现有全局元素和通用类规则，将可能影响应用壳或推荐工作区的规则限定到 `.video-workspace`。全局只保留明确共享的 reset 和基础变量。

推荐表格继续支持横向滚动，并保留现有 980px 和 640px 响应式行为。工作区切换不得改变播放器固定区域、视频列表滚动区或推荐表格的可用宽度。

## API 与构建

两个工作区继续使用同源相对路径调用后端，不增加新的服务端接口。推荐控制台的接口保持在 `/api/admin/recommendation/*` 下；视频工作区现有 REST 接口和响应兼容逻辑保持不变。

`hls-web/vite.config.js` 已代理 `/api`、`/videos` 和 `/swagger`，是两个旧项目代理需求的超集，因此继续作为唯一开发代理配置。开发端口继续为 5173，Docker Compose 继续挂载和启动 `hls-web/`，无需增加第二个前端服务。

## 错误与生命周期处理

- 登录失败只在统一登录页显示“账号或密码不正确”，不得挂载任一工作区。
- 浏览器存储读取或写入失败时不阻断页面；登录可在当前页面内继续使用，但刷新后可能需要重新登录。
- 视频和推荐接口错误继续由各工作区在原位置展示，不提升为全局错误。
- 每个工作区拥有并清理自身创建的定时器、媒体实例、监听器和订阅。切换时当前工作区先卸载并执行清理钩子，再挂载目标工作区并启动轮询；任意时刻最多存在一套工作区轮询。
- 退出时卸载当前工作区、清除登录状态并返回登录页。

## 文件边界

预期的核心文件职责如下：

- `hls-web/src/App.vue`：统一应用壳。
- `hls-web/src/config/consoleSession.js`：固定凭据、登录状态和当前工作区存储 helper。
- `hls-web/src/config/consoleSession.test.js`：登录和工作区状态单元测试。
- `hls-web/src/workspaces/VideoWorkspace.vue`：原视频调试台业务页面。
- `hls-web/src/workspaces/RecommendationWorkspace.vue`：推荐控制台业务页面，不含登录。
- `hls-web/src/recommendation/api/http.js`：推荐控制台 JSON 请求 helper。
- `hls-web/src/recommendation/api/recommendationConsole.js`：推荐管理 API helper。
- `hls-web/src/recommendation/api/recommendationConsole.test.js`：推荐 API 契约测试。
- `hls-web/src/recommendation/components/PreviewTable.vue`：推荐预览结果表。
- `hls-web/src/recommendation/config/navigation.js`：推荐控制台内部导航和链路说明。
- `hls-web/src/recommendation/config/sectionSession.js`：推荐子栏目存储与有效性校验。
- `hls-web/src/recommendation/config/sectionSession.test.js`：推荐子栏目恢复、回退和持久化测试。
- `hls-web/src/recommendation/recommendation.css`：限定在推荐工作区根节点内的样式。

为保持修改可控，本次不把视频工作区进一步拆分为多个业务组件，也不统一两套 API 客户端。

## 测试策略

实施前分别运行两个旧项目的现有测试，记录基线。实施采用测试驱动方式：

1. 先为统一登录、登录状态恢复、有效工作区恢复、无效工作区回退、退出清理、旧登录键删除和存储方法抛错写失败测试。
2. 实现最小统一会话 helper，使测试通过。
3. 迁移推荐 API 测试，以及推荐子栏目恢复、非法值回退和仅持久化有效栏目测试；先确认新路径缺少实现时测试失败，再迁移实现使其通过。
4. 迁移两个工作区并完成应用壳；将 `adminLayout.test.js` 的视频布局检查目标从 `App.vue` 更新为 `VideoWorkspace.vue`。
5. 运行 `hls-web` 全量 Vitest 和生产构建。
6. 在浏览器中验证桌面与窄屏流程。

浏览器验收使用 `1440x900` 桌面视口和 `390x844` 移动视口，覆盖错误凭据、正确登录、默认视频工作区、两个工作区切换、刷新恢复、推荐七个栏目、退出、重新登录和响应式布局，并保存关键页面截图。浏览器控制台不得出现新增的运行时错误，页面元素不得溢出或相互遮挡。切换或退出后旧工作区不得继续发起轮询请求，重新进入只能启动一套轮询。

## 文档与删除

更新 `hls-web/README.md`，说明统一 UI 门禁、两个工作区、启动命令、唯一开发端口和门禁不等于安全鉴权的警告，并迁入旧推荐 README 中仍有效的接口与模块说明。更新根 `README.md` 和 `docs/README.md`，删除对独立 `recommendation-console/` 项目的说明。

两个旧项目测试基线已记录，迁移后 `hls-web` 全量测试和生产构建通过，视频与推荐浏览器回归、工作区卸载清理、Docker Compose 配置校验及文档更新全部完成后，方可删除整个 `recommendation-console/` 目录。删除范围只包含该前端项目，不触碰当前工作区中与本任务无关的 Go 文件修改。

## 验收标准

1. 仓库只保留 `hls-web/` 作为本次涉及的前端工程，`recommendation-console/` 不再存在。
2. 未登录时无法从界面进入任一工作区。
3. 固定账号 `aaddmmiinn` 和密码 `admin123` 可登录，错误凭据显示明确错误。
4. 登录一次即可进入视频调试台和推荐控制台，两个工作区共用同一退出操作。
5. 切换工作区后只挂载当前工作区，刷新可恢复最后工作区。
6. 视频调试台现有功能和测试保持可用。
7. 推荐控制台七个栏目、现有 API 契约和测试保持可用。
8. `npm test` 与 `npm run build` 在 `hls-web/` 中成功完成。
9. `1440x900` 和 `390x844` 视口下，登录页、顶部切换、视频工作区和推荐工作区无溢出或遮挡，并留存关键截图。
10. 根 Docker Compose 配置校验通过，`frontend_web` 继续挂载并启动 `hls-web/`，不新增第二个前端服务。
