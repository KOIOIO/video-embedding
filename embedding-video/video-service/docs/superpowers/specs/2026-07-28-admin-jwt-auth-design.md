# 管理员 JWT 鉴权设计

## 目标

为后台控制面板增加 JWT 登录与路由级鉴权。管理员由 `sys_user.user_type = 3` 判定，并且账号必须满足 `status = 1`、`deleted = 0`。管理类接口只允许有效管理员访问；播放、推荐、观看记录和互动接口保持现有公开行为。

## 管理员认证

新增 `POST /api/auth/login`。请求使用 `username` 和 `password`，服务端从 `sys_user` 查询账号，使用 bcrypt 校验密码，并检查管理员类型、启用状态和未删除状态。成功响应返回 JWT 和管理员基本信息；失败统一返回未授权错误，不泄露账号是否存在。

JWT 使用配置提供的签名密钥和过期时间，令牌 subject 保存 `sys_user.id`。新增 `GET /api/auth/me` 用于恢复前端登录状态。除登录、健康检查和公开资源外，路由必须携带 `Authorization: Bearer <token>`。中间件解析令牌后，每次请求重新查询 `sys_user`，因此账号被禁用、删除或降级后已有令牌立即失效。

## 路由边界

公开路由包括健康检查、Swagger 以外的播放媒体、问题查询、视频/知识点播放、按问题推荐、随机播放、推荐列表、观看记录、点赞/点踩及其统计、知识点播放记录和 RecBole 外部推荐。管理路由包括系统指标、普通视频和知识点视频的全部上传流程、上传进度、视频列表管理操作（修改、删除、封面、发布、人工推荐）、转码状态以及 `/api/admin/recommendation/**` 管理分析接口。Swagger 和 `GET /api/auth/me` 需要管理员 JWT。

后端使用公开路由组和管理员路由组统一挂载中间件，兼容路径与主路径保持相同鉴权策略，避免单独 Handler 鉴权遗漏。

## 上传者身份

普通视频上传、普通视频分片上传、压缩包上传、压缩包分片上传和知识点视频批量导入不再信任客户端的 `user_id` 或 `upload_user_id`。请求通过 JWT 鉴权后，从上下文取得管理员 ID，写入视频或知识点视频批次的上传者字段。分片上传会在服务端会话中保存该管理员 ID，完成阶段继续使用会话值；客户端提交的上传者字段被忽略或拒绝。

公开接口中的业务用户 ID 不变：观看记录、知识点播放记录、按问题推荐、随机播放、点赞/点踩等继续按现有协议接收 `user_id`，它表示行为主体而非资源上传者。

## 前端

`hls-web` 新增管理员登录页、JWT 持久化和统一请求鉴权。管理类 fetch/XHR 自动添加 Bearer 令牌，收到 401/403 清理登录状态并跳转登录页。两个上传界面移除上传者 ID 输入和字段。公开播放、推荐、观看和互动请求不改变 URL、请求体或业务逻辑；共享请求封装可以选择性携带令牌，但公开接口不依赖令牌。

## 错误与安全

缺少或无效令牌返回 401，令牌有效但账号当前不再具备管理员资格同样返回 401；请求格式或业务校验错误仍返回现有 400。密码只保存/比较 bcrypt 哈希，日志不得输出密码或完整 JWT。JWT 密钥缺失时服务启动失败，避免以空密钥运行。

## 测试策略

后端测试覆盖：管理员成功登录、非管理员/禁用/删除账号拒绝、错误密码拒绝、令牌解析与过期、公开路由免鉴权、管理路由缺少或错误令牌拒绝、账号降权后旧令牌失效、普通视频和知识点视频上传使用 JWT 管理员 ID 且忽略客户端上传者字段。前端测试覆盖：登录持久化、管理请求带令牌、401 自动退出、上传请求不包含上传者字段、公开请求保持现有参数。
